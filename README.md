# Category Classifier

상품 URL을 입력받아 **크롤링 → 정보 추출 → BERT 기반 카테고리 분류 → KoSimCSE 임베딩 생성 → MongoDB 저장**까지 자동으로 처리하는 비동기 파이프라인 프로젝트입니다.  
MongoDB Change Stream, Celery, Redis, Selenium, BERT 등 다양한 구성요소가 조합되어 대규모 상품 데이터 처리를 자동화합니다.

---

## 📌 프로젝트 개요

Category Classifier는 다음과 같은 흐름으로 동작합니다.

1. MongoDB에 상품 문서가 등록됨  
2. Change Stream이 새 문서를 감지  
3. Celery 태스크로 상품 URL 크롤링 실행  
4. 크롤링한 텍스트 기반으로 카테고리 분류 및 임베딩 생성  
5. 최종 결과를 다시 MongoDB에 업데이트  

상품 수집부터 분석까지 완전 자동화된 **엔드투엔드 파이프라인**을 제공합니다.

---

# 1. 서버 구성요소

프로젝트는 다음과 같은 구성으로 이루어져 있습니다.

### **✔ Crawler (크롤링 레이어)**
- Selenium 기반 웹 드라이버 사용  
- 각 도메인별 파서로 상품명·가격·상세정보 등 구조화된 데이터 추출  
- 크롤링 결과를 모델 입력에 적합한 텍스트 형태로 변환  

### **✔ Model (모델 레이어)**
- Fine-tuning된 BERT 계열 모델로 상품 카테고리 분류  
- KoSimCSE SentenceTransformer 모델로 텍스트 임베딩 생성  
- 임베딩은 검색·추천 시스템에 활용 가능  

### **✔ MongoDB (데이터 레이어)**
- 원본 상품 데이터 저장  
- 크롤링 및 분석 결과 업데이트  
- Change Stream을 통해 데이터 변경 실시간 감지  

### **✔ Celery + Redis (비동기 처리 레이어)**
- Redis: Celery의 broker 및 backend  
- 크롤링, 분류, 임베딩 생성 작업을 비동기로 처리  
- 대량 URL 처리 시 서버 부담 없이 안정적 동작  

### **✔ Logging Layer**
- JSON 형식의 구조적 로그 출력  
- 오류 추적 및 서비스 운영에 최적화  

---

# 2. 어떻게 크롤링하는지

크롤링은 다음 절차로 진행됩니다.

### **1) URL 기반 파싱 라우팅**
도메인에 따라 전용 파서가 선택됩니다.


각 사이트는 HTML 구조가 다르므로 개별 파서로 세부 정보 추출합니다.

### **2) Selenium 기반 페이지 로딩**
- 실제 브라우저 환경을 사용하여 동적 콘텐츠까지 확보  
- Anti-bot 탐지 우회 옵션 적용  

### **3) HTML 분석 및 데이터 추출**
- 상품명  
- 가격  
- 옵션 및 상세 스펙  
- 설명 텍스트  
- 이미지 정보  
- 기타 상품 속성  

### **4) 텍스트 정제**
불필요한 키워드·중복 정보 제거 후  
BERT 입력에 적합한 텍스트로 변환합니다.

---

# 3. 모델 어떻게 학습 및 임베딩

모델은 크게 두 가지 역할을 수행합니다.

---

## 🔹 A. BERT 기반 카테고리 분류

### 특징
- Hugging Face BERT 계열 모델 사용  
- 상품명 + 가격 + 상세정보를 기반으로 분류  
- LabelEncoder로 문자열 카테고리 매핑

### 입력 구성 예시
[TITLE] 상품명
[INFO] 가격 정보, 주요 스펙, 상세 설명...


### 출력  
- 예: 의류 / 식품 / 뷰티 / 리빙 / 전자기기 등  

---

## 🔹 B. KoSimCSE 기반 문장 임베딩

### 특징
- `BM-K/KoSimCSE-roberta-multitask` 사용  
- 한글 문장 유사도에 최적화  
- 출력 임베딩은 검색/추천에 활용 가능한 벡터  

### 임베딩 활용 예
- 상품 유사도 검색  
- 추천 시스템  
- 벡터 기반 키워드 매칭  

---

# 4. Redis 처리

Redis는 **Celery 비동기 처리의 핵심**입니다.

### 역할 요약
- Celery 브로커: 작업 전달 담당  
- Celery 백엔드: 작업 상태 저장  
- 대규모 URL 처리 시 확장성과 안정성을 보장  

---

# 5. 사용방법

다음은 프로젝트 실행 방법입니다.

---

## 🔧 1) 환경 설정

- 필요한 Python 패키지 설치  
- `.env` 파일 생성하여 MongoDB / Redis / 모델 경로 설정


---

## 🔧 2) 임베딩 모델 다운로드
KoSimCSE 모델을 로컬에 저장해 둡니다.  
추론 시 인터넷 접속 없이 빠르게 처리할 수 있습니다.

---

## 🔧 3) Celery 워커 실행
크롤링 워커와 추론 워커를 각각 실행하는 것이 일반적입니다.

---

## 🔧 4) MongoDB Listener 실행
상품 문서가 MongoDB에 입력되면  
Change Stream이 자동으로 감지하여 파이프라인이 시작됩니다.

---

## 🔧 5) 전체 파이프라인 작동 흐름

| 단계 | 설명 |
|------|-------|
| 1 | MongoDB에 상품 URL 포함 문서 입력 |
| 2 | Change Stream이 실시간으로 문서 감지 |
| 3 | Celery로 URL 크롤링 작업 실행 |
| 4 | 크롤링된 텍스트 기반 분류 & 임베딩 생성 |
| 5 | 결과 MongoDB에 최종 업데이트 |

모든 과정은 자동으로 백그라운드에서 수행됩니다.

---

# 📌 요약

Category Classifier는  
**“상품 URL만 넣으면 자동으로 카테고리/임베딩까지 생성되는 시스템”**입니다.

- 자동 웹 크롤링  
- Fine-tuned BERT 분류  
- KoSimCSE 임베딩  
- 비동기 Celery 파이프라인  
- MongoDB 실시간 감지  
- Redis 기반 안정적 분산 처리  

서비스형 시스템 구축, 대규모 데이터 전처리, 추천·검색 시스템의 백엔드로 활용하기 매우 적합합니다.
